The four the review left to me

Six of the eight criticals had a right answer in your documents. These four don't — they need a decision about how something looks. Each is drawn from DESIGN.md tokens only; no new colours, no new type.

Under each set is the same thing rendered in greyscale, because three of these four exist specifically because something currently depends on colour alone. If an option stops working in grey, it has failed the test it was built for.

Critical · rubric

1 · Where a Span lives

A Span Service — the lawn across Haldi and Wedding — is one Selection contributing once. The By-Function workspace lists it under every day it serves, and the PRD names the failure exactly: counting per Function posts ₹7,20,000 for a ₹2,40,000 lawn. The UI must make the single-ness visible. EXPERIENCE.md calls this the highest-risk pattern in the product; DESIGN.md never said how to draw it.

Critical · rubric

2 · The availability signal

Three states, never two — a Vendor shows available, shows unavailable, or has said nothing. The third is not a failure and must not look like one: it happens whenever there is no Anchor Date yet, or the Service has no duration, or the Listing has no active Subscription. Each state needs a glyph and a word. No glyph was ever named.

A · One ring, three treatmentschosen

One ring, three treatments. Nothing is red, nothing is green.

Shows unavailable Booked out on 27 November
Not stated This vendor hasn't set dates yet

Survives grey completely. Solid ring, thin ring, dashed ring — the border style alone separates all three, before colour or glyph. Note the copy says shows available, never available.

No glyph at all. The state is a phrase and nothing else.

Unambiguous, and slow. Fine in a list row, useless on a vendor card in a grid where there is room for a mark but not a sentence.

Critical · rubric

3 · What the screen shows while it waits

There is no loading state anywhere in 1,110 lines, in a product whose stated target is mid-range Android phones on patchy mobile data, often at a venue or in a market. Every prototype assumes the data has already arrived.

A · Skeleton of the real thingchosen

The shape of what is coming, in hairline, with a slow sheen.

The layout does not jump when content lands, which on a slow connection is the difference between a calm screen and a flickering one. Uses only {colors.hairline}; the sheen is a transform, so it costs nothing on a weak GPU.

B · A spinnerrejected

One mark in the middle, honest and content-free.

Loading venues near Shrirampur…

Cheapest to build, worst to wait on. It says nothing about how much is coming, and the layout jumps when it resolves. On a two-bar connection this is the screen someone stares at for eight seconds.

C · Named progressrejected

Says what it is doing, in the product's own voice.

Checking who's free across all three of your dates…
4 of 11 venues checked

Best for the one screen that earns it — cross-service block matching genuinely takes time and this makes the wait feel like work being done. Overkill everywhere else, and a lie if the number is invented.

Critical · accessibility
